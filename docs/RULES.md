# Little Q 运行规则

本文说明数据、权限、QCA 资源和交付边界。安装条件、组件库、全部环境变量和三种部署操作统一见 [部署手册](DEPLOYMENT.md)，不要根据开发机现状推断新环境配置。

## 1. 数据持久化

### 1.1 数据库选择

应用始终使用 PostgreSQL 数据模型，二选一：

| 条件 | 实现 | 数据位置 |
| --- | --- | --- |
| `DATABASE_URL` 非空 | 外部 PostgreSQL，通过 `postgres` 连接 | 所配置的数据库服务器 |
| `DATABASE_URL` 为空 | 随应用安装的 PGlite | `PGLITE_DIR`，本地默认 `./.data/pglite` |

首次业务查询时自动执行幂等表结构初始化，无需另跑迁移命令；修改表结构仍需同步调整初始化 SQL。PGlite 是有磁盘持久化的嵌入式 PostgreSQL，不是无数据库模式。`/api/health` 返回 `db.kind`，可确认实际后端。

### 1.2 数据归属

| 数据 | 存储 |
| --- | --- |
| 用户、角色、年龄段、头像和 scrypt 加盐密码哈希 | `users` |
| 登录状态 | `sessions` 与浏览器 HttpOnly Cookie，Cookie 有效期 30 天 |
| 作品当前 HTML、名称、发布状态与可见范围 | `projects` |
| 作品历史版本 | `versions` |
| 创作对话的页面记录 | `messages` |
| 点赞与浏览计数 | `likes`、`projects.likes / views` |
| 班级、成员、作业、提交与评价 | `classes`、`class_members`、`assignments`、`submissions` |
| QCA 环境、模板、身份等资源 ID | `qca_refs` |
| 作品创作会话 | `projects.agent_session_id`、`agent_seen_seq` |
| 观众与作品角色的对话关联 | `agent_chats` |
| 三套界面主题偏好 | 浏览器 `littleq-theme` Cookie，不入库、不跟随账号 |

作品不是磁盘静态 HTML 文件。分享页 `/w/{slug}` 与沙箱页 `/r/{id}` 按访问权限从数据库读取内容；QCA 也保留云端会话上下文，应用保存其关联 ID。

### 1.3 部署与备份

| 场景 | 要求 |
| --- | --- |
| 本地 / 虚拟机，PGlite | 单进程访问持久化目录，固定工作目录或设置绝对 `PGLITE_DIR` |
| Docker，PGlite | 持久化卷挂 `/app/.data`；Compose 已配置，容器目录为 `/app/.data/pglite` |
| Vercel | 必须外部 `DATABASE_URL`，不可使用临时文件系统持久化业务数据 |
| 多实例 | 必须外部 PostgreSQL，不能让多个进程共享 PGlite 目录 |
| 备份 | PostgreSQL 使用数据库服务备份或 `pg_dump`；PGlite 停止所有写入进程后完整复制数据目录 |

更换数据库相当于使用另一套用户、作品和班级数据；两套部署连接同一数据库会共享业务数据。开发、测试、Preview 与 Production 应使用独立数据库。源码清理、镜像更新不应删除已有业务数据库或数据卷。

## 2. QCA 资源与会话

### 2.1 部署级 Key

服务端 `QODER_API_KEY` 是整个部署使用的 QCA PAT，不是学生或老师的个人配置。用户注册、登录不需填写 Key，浏览器不会收到它。百炼 Key 使用另一个变量 `AI_API_KEY`；具体填写位置与后端选择见部署手册。

### 2.2 资源创建规则

程序按需查找和创建资源，并在数据库保存对应关系：

| 资源 | 归属与创建时机 |
| --- | --- |
| Environment `littleq-runtime` | 默认全部署共用；首次需要模板时查找或创建，可用 `QCA_ENVIRONMENT_ID` 指定 |
| 创作伙伴 Template | 全平台用户共用；名称含提示词与 `QCA_MODEL` 的哈希；首次创作或主动 AI 健康检查时准备 |
| 作品角色 Template | 每个作品、每种角色设定一份；名称含作品 ID、设定和 `QCA_AGENT_MODEL` 哈希；首次角色聊天时准备 |
| Identity | 每个应用用户一个；未登录访客使用共同的 `littleq:guest` 身份 |
| 创作 Session | 每个作品一个当前长期会话，首次创作时建立 |
| 角色 Session | 每个观众每次打开作品的一段对话，首次发言时建立；由外层页面生成对话标识 |

所有模板目前使用 `tools: []`，不执行模型生成的代码、不启动 QCA 代码沙箱。环境是 QCA 模板的关联运行配置；真实作品代码在浏览器 iframe 内展示。

### 2.3 复用与更新

- 同一个作品的持续修改复用创作会话；代码未变化时不重复传递当前版本。
- 模板身份由提示词 / 角色设定和模型计算；修改相关配置会使用对应的新模板。旧模板不会因版本变更自动全部归档。
- `qca_refs` 按 Key 指纹分开记账。更换 QCA Key 后在新账号查找或创建资源，不复用旧账号的资源 ID。
- 更换模板、Key 或失效会话后，创作会话可重建；当前代码和应用保存的近期对话用于恢复创作上下文，页面历史记录不因此清空。
- 角色设定变化后，新对话使用新模板；访问历史作品版本时使用该版本的设定。
- 刷新作品页或重新打开会建立新的角色对话标识；“重新开始”会归档旧角色会话。
- 删除作品会尽力归档其创作会话、观众会话及相关角色模板；云端清理失败不阻止应用内删除。
- 手工删除 / 改名云端资源可能破坏复用关系。运维清理资源前应核对关联；需要清理数据库资源缓存时先备份，并重启应用以清除进程内缓存。
- 多实例使用外部数据库共享资源记录；进程内请求去重不能替代跨实例并发控制，生产验收需覆盖并发使用与资源配额。

`AI_PROVIDER=bailian` **只切换创作伙伴**。智能体作品里的 AI 角色始终使用 QCA，缺少 `QODER_API_KEY` 时角色聊天不可用。

### 2.4 用量与权限

默认每段角色对话配置 40 轮上限，日轮数检查阈值为 400，可用 `AGENT_TURNS_PER_CHAT` 与 `AGENT_DAILY_LIMIT` 配置。日轮数按现存对话记录汇总；重置对话会删除旧计数，并发检查也不是原子预扣，因此该阈值不是不可绕过的计费硬上限。需要严格费用控制时应在云端账号 / 网关设置额度，并在上线验收中核对。应用不提供充值、付费额度管理或独立后台；云端 API 额度及费用由部署方管理。

作品可见范围为仅自己、班级或公开。作品 HTML 在不具备同源权限的 iframe 沙箱中运行，不能读取主站 Cookie；角色调用经 `postMessage` 与服务端 API 转发，Key 不进入作品脚本。浏览器沙箱不是独立网络防火墙，不能仅凭 iframe sandbox 宣称阻止所有外部网络请求。

账户使用用户名与密码登录；当前没有邮箱 / 短信认证或找回密码流程。老师可批量创建学生账号并接收初始密码，应通过安全渠道交付。面向未成年人的公开运营需按实际业务配置内容审核、隐私保护与运营流程；提示词约束不能替代独立的安全审核措施。

## 3. 作品广场与上线数据

首页最新作品与广场仅展示当前数据库中已发布且 `visibility='public'` 的作品。交付代码不内置用户、示例作品或自动 seed 脚本；新数据库展示空广场属于正常行为，不是部署缺文件。

上线如需精选作品，应由运营账号在正式环境创建、审核并发布，或使用部署方另行维护并审核的数据导入流程。不要把开发数据库整体复制到正式环境，也不要把 `npm run smoke` 当成初始化命令：它会在目标库创建测试账号、调用 AI 并公开发布测试作品。
